# สเปกเนื้อหาหน้าชนิด (8 ส่วน)

ใช้กับแผนค้นคว้า v1.1 (`docs/content-research-plan.md`) ทุกชนิดที่จะเติมเนื้อหาต้องเขียนตามสเปกนี้
โครงสร้างข้อมูลอยู่ใน `schema/organism.schema.json` (`extra_th`, `extra_en` และช่องระดับชนิด) ตัวตรวจอยู่ใน `python scripts/microsearch.py validate`
ความครบดูจาก `python scripts/microsearch.py coverage` → `reports/content-coverage.md`

## กติกาที่ใช้กับทุกส่วน

1. **เขียนด้วยคำของเราเอง** อ่านแหล่งแล้วปิดแหล่งก่อนเขียน ไม่คัดลอกประโยคจากแหล่งหรือจาก Wikipedia ไม่แปลตรงตัวทีละประโยค
2. **ข้อเท็จจริงทุกข้อมีอ้างอิงใน `refs`** (ตัวเลข ชื่อ ปี ช่วงอุณหภูมิ ข้ออ้างเรื่องโรค ฯลฯ) หาแหล่งไม่ได้ให้เว้นว่าง ไม่เดา และจดเหตุผลลงช่องหมายเหตุของ Sheet ติดตาม
3. **ข้อมูลการแพทย์** มีได้แค่: ชื่อโรค อาการหลัก การติดต่อ การป้องกัน และกลุ่มยาแบบกว้าง (เช่น "ยาปฏิชีวนะ") **ห้ามมีชื่อสูตรยา ชื่อการค้า หรือขนาดยา** validate ปฏิเสธข้อความใน `disease` ที่มีตัวเลขตามด้วย mg, g/kg, ml, "ครั้งต่อวัน"
4. ไม่เพิ่มรูป ส่วนเชื่อมบทเรียน หรือส่วน "ในประเทศไทย" (ตัดออกตามที่ตกลงแล้ว)
5. ศัพท์ไทยเทียบราชบัณฑิตยสภา ถ้าไม่แน่ใจให้ถามผู้ใช้ ไม่ตัดสินเอง
6. ทุกชนิดยังเป็น `review: ai_draft` จนผู้ใช้ตรวจ
7. ไทยก่อน อังกฤษแปลจากไทยที่นิ่งแล้ว (เฟส R9) ไม่เพิ่มข้อเท็จจริงใหม่ตอนแปล
8. ชื่อวิทยาศาสตร์เป็นตัวเอียงบนเว็บอยู่แล้ว ในข้อความให้เขียนชื่อสกุลเต็มครั้งแรก ถัดไปย่อได้ (*E. coli*)

## รูปแบบแถวของตาราง

`traitsExtra`, `life`, `lifecycle`, `why`, `name` เป็นรายการของแถว `[ป้าย, ข้อความ]` แสดงเป็นรายการ ป้าย: ข้อความ ส่วน `aside` เป็นรายการข้อความ

## 1 หัวเรื่อง

**เก็บ:** `authority` (ข้อความ), `synonyms` (รายการชื่อ), `accepted_name` (ชื่อเดียว)

**กติกา**
- `authority` เขียนตามรูปแบบในฐานข้อมูลของกลุ่ม (วงเล็บและปีตามที่ฐานข้อมูลให้) ตรวจจาก GBIF กับฐานข้อมูลเฉพาะกลุ่ม ถ้าสองแหล่งไม่ตรงกันให้ใช้ของฐานข้อมูลเฉพาะกลุ่มและจดความต่างใน Sheet
- `synonyms` ใส่เฉพาะชื่อที่ยังพบในตำราหรือบทความที่นักเรียนอ่าน ไม่ใส่ชื่อพ้องทุกชื่อ
- **นโยบายชื่อ (ตัดสินแล้ว 13 พ.ย. 2026):** คงชื่อตำราเป็น `scientific_name` (ชื่อหลัก) ถ้าชื่อที่ยอมรับปัจจุบันต่างออกไปให้ใส่ใน `accepted_name` หน้าเว็บแสดงทั้งสองชื่อ อย่าใส่ `accepted_name` ที่เหมือน `scientific_name` (validate จะแจ้ง error) และถ้าฐานข้อมูลหลักไม่ตรงกันเอง (เช่น *Burkholderia pseudomallei*) ให้ไม่ใส่ จดไว้ให้ผู้ใช้ตัดสิน

**ตัวอย่าง** (รูปแบบเท่านั้น ใช้ *Escherichia coli*)

```json
"authority": "(Migula 1895) Castellani & Chalmers 1919",
"synonyms": ["Bacterium coli"]
```

## 2 รู้จักใน 30 วินาที (`extra.lede`)

**ความยาว:** 2–3 ประโยค

**กติกา:** ตอบสามข้อตามลำดับ: เป็นอะไร (กลุ่มและลักษณะที่ทำให้แยกได้) อยู่ที่ไหน สำคัญอย่างไร ไม่ใส่ตัวเลขที่ต้องอ้างอิงยาวๆ ในส่วนนี้ ถ้ามีให้ตัวเลขเดียว

**ตัวอย่าง** (*Halobacterium salinarum* ที่มีอยู่)

> อาร์เคียที่อยู่ได้ในน้ำเกลือเข้มข้นจนสิ่งมีชีวิตส่วนใหญ่ตาย พบในบ่อตากเกลือและทะเลสาบน้ำเค็มจัด เซลล์มีรงควัตถุสีแดงและโปรตีนที่ใช้พลังงานแสงได้ จึงเป็นทั้งตัวทำให้นาเกลือเป็นสีชมพูและเป็นสิ่งมีชีวิตต้นแบบในงานวิจัย

## 3 ลักษณะเด่น

**เก็บ:** `traits` (ค่าเลือกและช่วงตัวเลขตาม `data/groups.json`), `traits_text_th/en` (ข้อความอิสระ), `extra.traitsExtra` (แถวเพิ่ม)

**ความยาว:** รวม 6–9 แถว

**กติกา**
- ลักษณะที่ตัวกรองใช้ได้ให้เก็บเป็นค่าเลือกใน `traits` (ไม่เขียนซ้ำเป็นข้อความ) ลักษณะที่เป็นช่วงตัวเลข (อุณหภูมิ pH ความเค็ม) เก็บเป็น `{"min": 40, "max": 55, "unit": "°C"}` หน่วยต้องตรงกับที่ `groups.json` กำหนด
- ถ้าไม่มีค่าที่เลือกได้ตรงกับชนิดนั้น อย่าฝืนเลือกค่าใกล้เคียง ให้ใช้ `traitsExtra` อธิบาย และเสนอค่าใหม่ใน `groups.json` ต่อผู้ใช้
- ค่าที่ได้จากฐานข้อมูลเฉพาะกลุ่ม (BacDive, POWO ฯลฯ) ต้องมี `refs` รองรับ

**ตัวอย่าง** (*Halobacterium salinarum*)

```json
"traitsExtra": [
  ["ผนังเซลล์", "ไม่มีเพปทิโดไกลแคน มีชั้นไกลโคโปรตีนที่เรียกว่า S-layer ย้อมแกรมติดสีแบบแกรมลบ"],
  ["ความเค็มที่เหมาะ", "NaCl ราว 4 โมลาร์ เข้มข้นกว่าน้ำทะเลประมาณ 7 เท่า"]
]
```

## 4 การดำรงชีวิต (`extra.life`)

**ความยาว:** 3–4 แถว

**กติกา:** แถวตามลำดับ: แหล่งที่อยู่ / การได้อาหารหรือพลังงาน / ความสัมพันธ์กับสิ่งมีชีวิตอื่น (อยู่ร่วม ปรสิต ถูกกิน) อาจมีแถวที่ 4 ถ้ามีเรื่องเฉพาะชนิดที่สำคัญ เช่น การปรับตัวต่อสภาพรุนแรง

**ตัวอย่าง** (รูปแบบ ใช้ *Escherichia coli*)

```json
"life": [
  ["แหล่งที่อยู่", "ลำไส้ใหญ่ของสัตว์เลือดอุ่นรวมทั้งคน และปนเปื้อนออกสู่ดินและน้ำได้"],
  ["การได้อาหาร", "ใช้สารอินทรีย์ ได้ทั้งแบบใช้และไม่ใช้ออกซิเจน"],
  ["ความสัมพันธ์", "ส่วนใหญ่อยู่ร่วมกับโฮสต์โดยไม่ก่อโรค บางสายพันธุ์ก่อโรคทางเดินอาหาร"]
]
```

## 5 การสืบพันธุ์และวงชีวิต (`extra.lifecycle`)

**ความยาว:** โพรแคริโอต 1 แถว 1 ประโยค; ฟังไจ โพรทิสต์ พืช และปรสิต 3–6 ขั้นตามลำดับ

**กติกา:** ป้ายคือชื่อขั้นหรือระยะ (เขียนเลขลำดับในป้ายถ้าเป็นวงจร) ข้อความบอกว่าเกิดอะไรและเกิดที่ไหน (โฮสต์ใด) ปรสิตต้องระบุโฮสต์ของแต่ละขั้น ไม่ใส่ขนาดหรือระยะเวลาที่ไม่มีอ้างอิง

**ตัวอย่าง** (รูปแบบ ใช้ *E. coli*: โพรแคริโอต)

```json
"lifecycle": [["การแบ่งเซลล์", "แบ่งตัวแบบไบนารีฟิชชัน เซลล์หนึ่งแบ่งเป็นสองเซลล์ที่เหมือนกัน"]]
```

## 6 ความสำคัญ (`extra.why`)

**ความยาว:** 1 แถวต่อแท็กของชนิด (`tags` ใน `groups.json`: การแพทย์ อาหาร นิเวศ เกษตร อุตสาหกรรม วิทยาศาสตร์) แถวละ 1–2 ประโยค

**กติกา:** ป้ายแถวคือชื่อแท็กตามที่เว็บแสดง ทุกแท็กที่ชนิดมีต้องมีแถว ไม่เพิ่มแถวที่ไม่มีแท็ก ข้อมูลการแพทย์ในแถวนี้อยู่ภายใต้กติกาข้อ 3

**ตัวอย่าง** (*Halobacterium salinarum*)

```json
"why": [
  ["นิเวศ", "เป็นสาเหตุหนึ่งที่ทำให้บ่อตากเกลือมีสีชมพูถึงแดง จากรงควัตถุแคโรทีนอยด์ชื่อแบคทีริโอรูเบอริน"],
  ["วิทยาศาสตร์", "แบคทีริโอโรดอปซินเป็นปั๊มโปรตอนที่ขับเคลื่อนด้วยแสง และเป็นโปรตีนเยื่อหุ้มเซลล์ที่ถูกศึกษาโครงสร้างมากที่สุดชนิดหนึ่ง"]
]
```

## 7 ชื่อนี้มาจากไหน + เกร็ด (`extra.name`, `extra.asideTitle`, `extra.aside`)

**ความยาว:** `name` 2 แถว (สกุล, ชนิด) และแถวเสริมได้ถ้าจำเป็น; `aside` 3–4 ข้อ ข้อละ 1 ประโยค; `asideTitle` 1 บรรทัด

**กติกา**
- ที่มาของชื่อต้องมีแหล่ง (พจนานุกรมชื่อวิทยาศาสตร์หรือเอกสารที่ตั้งชื่อ) ถ้าไม่แน่ใจที่มา ให้ไม่เขียนแถวนั้น
- เกร็ดเลือกเรื่องที่ทำให้เข้าใจชีววิทยาของชนิดนั้นลึกขึ้น หรือแก้ความเข้าใจผิดที่พบบ่อย ไม่ใช้เกร็ดที่เป็นเพียงความแปลก
- `asideTitle` ตั้งเป็นประโยคที่ชวนอ่านต่อ ไม่ใช่คำว่า "เกร็ดน่ารู้"

**ตัวอย่าง** (*Halobacterium salinarum*)

```json
"name": [
  ["Halobacterium", "มาจากภาษากรีก hals แปลว่าเกลือ รวมกับ bacterium"],
  ["salinarum", "ภาษาละติน แปลว่า ของนาเกลือ"]
],
"asideTitle": "ชื่อมีคำว่า bacterium แต่ไม่ใช่แบคทีเรีย",
"aside": [
  "ผนังเซลล์ไม่มีเพปทิโดไกลแคน ใช้ชั้นไกลโคโปรตีน S-layer แทน",
  "ลิพิดของเยื่อหุ้มเซลล์ต่อกันด้วยพันธะอีเทอร์ ส่วนแบคทีเรียใช้พันธะเอสเทอร์",
  "RNA polymerase และกลไกการถอดรหัสคล้ายของยูแคริโอตมากกว่าของแบคทีเรีย",
  "ชื่อสกุลตั้งไว้ก่อนที่นักวิทยาศาสตร์จะแยกอาร์เคียออกเป็นอีกโดเมน"
]
```

(ข้อมูลของ *Halobacterium salinarum* มีแถว "ชื่อพ้อง" อยู่ใน `name` ตั้งแต่ v1.0 ชนิดใหม่ให้ใช้ `synonyms` ของส่วน 1 แทน)

## 8 อ้างอิง (`refs`)

**ความยาว:** 2–5 แหล่ง

**กติกา**
- แต่ละแหล่ง: `title` (ชื่อหน้าหรือบทความ), `url` (ต้องขึ้นต้น `https://`), `accessed` (วันที่เข้าถึง `YYYY-MM-DD`)
- แหล่งต้องครอบคลุมทุกข้อเท็จจริงในส่วน 1–7 ถ้ามีข้อที่หาแหล่งไม่ได้ให้ตัดข้อนั้นออก
- ให้เลือกแหล่งตามกลุ่มจาก `docs/sources.md` ก่อน; Wikipedia ใช้เป็นทางเข้าหาแหล่งได้ แต่ไม่ใส่เป็นอ้างอิงหลัก

**ตัวอย่าง** (รูปแบบ ใช้ *E. coli*)

```json
"refs": [
  {"title": "NCBI Taxonomy: Escherichia coli", "url": "https://www.ncbi.nlm.nih.gov/Taxonomy/Browser/wwwtax.cgi?id=562", "accessed": "2026-11-14"},
  {"title": "LPSN: Escherichia coli", "url": "https://lpsn.dsmz.de/species/escherichia-coli", "accessed": "2026-11-14"}
]
```

## ส่วนเพิ่มเฉพาะบางชนิด

### `extra.disease` (เชื้อก่อโรคและปรสิต)

ออบเจ็กต์ที่ทุกช่องเป็นข้อความ: `name` (ชื่อโรค), `symptoms` (อาการหลัก), `transmission` (การติดต่อ), `prevention` (การป้องกัน), `drugs` (กลุ่มยาแบบกว้าง)
- ชนิดที่มี `disease` ต้องมีแท็ก `medicine`
- `drugs` เขียนระดับกลุ่ม เช่น "ยาปฏิชีวนะ" "ยาต้านปรสิต" ห้ามชื่อสูตร ชื่อการค้า ขนาด หรือความถี่ในการใช้
- ข้อความแนะนำให้ไปพบแพทย์อยู่ในข้อความคงที่ของเว็บ (`i18n`) ไม่ต้องเขียนซ้ำในทุกชนิด

### `extra.warning` (เห็ดพิษและสัตว์มีพิษ)

`text` (คำเตือนสั้นๆ ว่าอะไรเป็นอันตราย) และ `myths` (รายการสิ่งที่มักเข้าใจผิด เช่น "ต้มแล้วกินได้") ห้ามมีวิธีรักษาเองที่บ้าน

### `iucn` (พืชและสัตว์)

`{"category": "LC", "url": "https://www.iucnredlist.org/species/...", "assessed": "2020"}` หรือ `null` ถ้ายังไม่ได้ประเมิน ข้อมูลมาจาก API ของ IUCN อย่างเดียว **ห้ามคัดลอกข้อความประเมิน** หมวดที่ใช้: EX, EW, CR, EN, VU, NT, LC, DD, NE
